   - 왜 비싼가: 서버 저장 형식을 계획대로 짜면 가져오기·내보내기·Godot·폴더 연결이 모두 어긋난다.

2. **보드 주인이 정해지지 않았다** [확인]
   - 어디: `app.js:2476-2590`, `app.py:360`, 계획 6절, `SERVER_PLAN_RESEARCH.md` "아직 안 정함: 곡의 서버 저장".

3. **소리와 생성 요청이 지나갈 길이 없다** [확인, 일부 추정]
   - 어디: `studio_frontend/app.js:246`(`send`), `app.py:448`(1초 rerun), `app.py:427`(40만 자 제한), `app.js:1815`, `.streamlit/config.toml`.
   - 무엇: 올라가는 길은 `setComponentValue` 한 칸, 내려오는 길은 1초마다 다시 보내는 args뿐이다. `asset:prompt`는 호스트에 받는 코드가 없다. `request()`와 `fill()`은 타이머다(`app.js:1053`, `1808`). 생성용 메시지는 아직 없다.
   - 왜 비싼가: WAV를 args에 실으면 탭마다 매초 부담이 된다 [추정]. `static/`에 두면 인증 없이 열린다 [확인: `enableStaticServing`]. 연달아 보낸 이벤트는 앞의 것이 덮일 수 있다 [추정].

4. **버전이 소리가 아니라 레시피다** [확인]
   - 어디: `app.js:420`, `461`, `2490`, `2509`, `2521`.
   - 무엇: 버전은 `{change, note}`만 저장하고 들을 때 `synth.render`로 다시 만든다. audio 저장소는 에셋당 Blob 하나(가져온 원본)다. 용량이 차면 오래된 버전을 지운다.
   - 왜 비싼가: 실제 생성은 버전마다 바이트가 있어야 한다. 시안 4개를 기록에 남기는 약속과 겹치면 용량이 문제가 되고, 기존 사용자 보드를 옮겨야 한다.
   - 권장: 백엔드 전에 버전 레코드를 확정한다. 내용은 `{작업 id, 엔진, 소스, 측정값, 출처[], 프롬프트, 모델, 소리 키}`이고, Blob은 버전별 키로 둔다. 서버 보관 기한과 "다시 받기 불가"도 여기서 정한다.

5. **작업 수명이 화면과 맞지 않는다** [확인]
   - 어디: `app.js:2499`, `asset_agent.py:136-139`, `app.js:1140`, `studio_backend.py:1318`.

   - 왜 비싼가: 유료 생성에서 새로고침은 과금 후 결과 유실이 된다. 같은 계정의 두 탭은 서로 막는다.
   - 권장: 에이전트 호출(지금 구조 유지)과 생성 작업을 분리한다. 생성은 에셋·시안 단위 작업 id를 보드에 저장하고, 복원할 때 다시 붙는다. 전역 작업자 수를 제한하고 취소·부분 실패 환불을 둔다.

### 빼거나 순서를 바꿀 것

- MCP(순서 10)는 미룬다. 게임 폴더 연결이 이미 spec과 파일을 폴더에 쓰므로 외부 에이전트는 폴더를 읽으면 된다.
- 린터(순서 5)는 렌더 백엔드(순서 4)와 함께 간다. 측정값이 버전 레코드의 일부이기 때문이다.
- 9절의 "AI 정확도 측정"은 순서 6에서 순서 3으로 올린다.
- 효과음은 jsfxr 값(JSON)을 AI가 내고 브라우저가 렌더하면 서버 렌더·전송·코드 실행 문제 없이 지금 에이전트 경로로 먼저 붙일 수 있다 [추정]. 대신 "서버에서 렌더" 원칙과 갈린다.
