# strudel 딸깍이 — UI·폰트 위계 명세

작성: 2026-11-07 · 구현 전 명세 · [개발 계획](STRUDEL_PLAN.md)

## 1. 방향

이 화면의 사용자는 음악을 듣다가 한 부분이 마음에 안 들어 자연어로 고치려는 제작자다. 첫 시선은 현재 곡, 첫 행동은 재생이나 AI에게 수정 요청하기다. 검은 청취 공간에 앨범 아트, 밝은 재생 버튼, 트랙의 실제 리듬이 중심이 된다. 개발 대시보드처럼 로그·수치 카드가 주인공이 되지 않는다.

도메인 요소는 곡·마디·리듬·레이어·믹서·청취 구간이다. 색은 어두운 공연장, 흰 재생 버튼, 트랙 식별색에서 가져온다. 고유 요소는 **AI가 실제로 듣는 구간을 표시하는 청취 띠**다. 중앙 시각화, 트랙 패턴의 playhead, 하단 시간 표시, AI 진행 문장, 버전 비교 구간이 동일한 오디오 시계를 참조한다.

YouTube Music의 큰 아트·여백·음악 우선 구조와 Spotify의 하단 고정 플레이어를 참고한다. 서비스 로고나 브랜드 자산은 가져오지 않는다. 과도한 카드 격자 대신 중앙 감상 영역과 연속된 트랙 행을 사용한다. 코드는 고급 보기에서만, 기술 로그는 문제 세부정보에서만 보인다.

## 2. 화면 배치

```text
┌──────────────────────────────────────────────────────────────────┐
│ strudel 딸깍이  [프로젝트 ▾ / 곡 이름] [저장] [자동 개선 OFF] [설정] │
├───────────────────────────────────────────┬──────────────────────┤
│                                           │ AI와 만들기      [접기]│
│   [앨범 아트]   곡 이름                     │                      │
│                 BPM · 마지막 변경          │ 사용자 요청           │
│                                           │ 변경 요약             │
│   실제 출력 시각화 + 청취 구간 띠            │                      │
│                                           │ 00:08–00:16 듣는 중    │
│   트랙                                    │ 개선 1/3       [중단]  │
│   [드럼  선택]  패턴 ──────  [음소거] [음량] │                      │
│   [베이스   ]  패턴 ──────  [음소거] [음량] │                      │
│   [멜로디   ]  패턴 ──────  [음소거] [음량] │ [수정 요청 입력…] [↑] │
├───────────────────────────────────────────┴──────────────────────┤
│ 곡 이름        [재생 / 정지·지원 시 일시정지] 00:32  240 BPM  음량 │
└──────────────────────────────────────────────────────────────────┘
```

상단은 72px, 하단은 최소 96px를 초기 기준으로 둔다. 본문은 남은 높이를 쓰고, 트랙과 채팅은 각자 스크롤한다. 하단 공간을 실제 layout row로 확보해 마지막 트랙이나 채팅 입력창을 덮지 않는다. 채팅 초기 너비는 400px, 범위는 320–640px, 분할선을 끌어서 조절한다. 접으면 중앙 영역을 넓히고 ‘AI 열기’ 버튼을 남긴다.

앨범 아트는 기본 256px 사각형이며 폭·높이가 부족하면 160px로 줄인다. 초기 아트는 프로젝트의 고정된 기본 그래픽으로 충분하다. 매 생성마다 이미지 모델을 호출하지 않는다. 중앙 시각화는 실제 출력/패턴 데이터가 있을 때만 움직인다.

### 좁은 화면과 확대

- 1280×720에서는 중앙 아트와 트랙을 압축하되 글씨를 자동 축소하지 않는다.
- 1100px 미만 또는 확대 시 채팅은 기본 접힘. 열면 주 영역을 대체하는 패널로 제공하고 돌아갈 수 있게 한다.
- 720px 미만에서는 상단에 이름·프로젝트·설정을 유지하고 저장/자동 개선을 펼침 영역으로 보낸다. 트랙 음량은 선택한 트랙에서 펼친다.
- 200% 확대에서 가로 스크롤 없이 핵심 조작 가능. 글씨가 커지면 상·하단도 내용에 맞게 늘어난다.
- 프로젝트 전환·게임 진입은 저장 상태 확인과 연결한다. 저장 실패 시 내보내기/다시 시도를 제공한다.

## 3. 폰트 위계

한국어는 **Noto Sans KR** 한 패밀리로 통일한다. 한글 가독성과 TINProject에서 확인한 큰 글씨 선호를 반영했다. 숫자는 같은 폰트의 tabular-nums, 고급 코드만 monospace를 쓴다. 본문은 18px이며 설정에서 100/125/150/200%로 키울 수 있다. 아래 px는 기본 배율의 환산값이고 실제 구현은 rem을 사용한다.

| 역할 | 크기 / 줄 높이 | 굵기 | 사용처 |
|---|---|---|---|
| 곡 제목 H1 | 32 / 42px | 700 | 중앙 현재 곡. 화면에서 가장 강한 텍스트 |
| 영역 제목 H2 | 22 / 32px | 600 | 트랙, AI와 만들기, 설정 |
| 본문 | 18 / 29px | 400 | 채팅, 분석 설명, 오류 안내 |
| 조작 라벨 | 18 / 26px | 600 | 재생, 저장, 프로젝트, 트랙 이름 |
| 보조 정보 | 16 / 24px | 400 | BPM 설명, 저장 시각, 버전 요약 |
| 시간·BPM | 18 / 26px | 500 | tabular-nums, 값 갱신 때 폭 고정 |
| 고급 코드 | 16 / 26px | 400 | monospace, 별도 확대 가능 |

작은 uppercase 영문 장식이나 과도한 자간은 넣지 않는다. 긴 곡 제목은 중앙에서 두 줄까지 허용하고 상단에서는 말줄임+전체 이름 접근을 제공한다. 중요한 오류와 자동 개선 상태는 작거나 흐린 caption으로 숨기지 않는다.

| `status-success` | `#8BD7A4` | 저장 성공·적용 완료 |

트랙 식별색은 드럼 `#E8AE72`, 베이스 `#87B9E8`, 멜로디 `#C7A0E8`, 패드 `#8CCDB2`를 초기 팔레트로 둔다. 전체 카드 배경을 물들이지 않고 아이콘·작은 표시·pattern event에만 쓴다. 트랙색은 상태색으로 쓰지 않으며 아이콘·이름·선택 테두리를 함께 표시한다. 트랙이 늘어나도 이름으로 구별할 수 있어야 한다.

깊이는 면의 밝기 차이로 표현한다. 큰 그림자·장식 그라디언트는 쓰지 않는다. 간격은 4px 단위: 4/8/12/16/24/32/48. 버튼 radius 8px, 패널 12px, 아트 12px, 모달 16px. 기본 버튼 높이 48px, 아이콘의 hit area도 48px. 재생 버튼은 56px. hover는 면의 밝기, active는 눌림, focus는 명확한 테두리로 구별한다.

사용 가능한 모든 텍스트는 실제 배경과 WCAG AA 대비를 검사한다. disabled 색은 읽어야 하는 상태 설명에 사용하지 않는다. 폰트는 필요한 weight와 한국어 분할 subset을 사용하고 `font-display: swap`, 네트워크 실패 시 한국어 시스템 글꼴로 대체한다.

## 5. 핵심 상호작용

### 트랙

행 높이는 최소 64px, 기본 72px다. 선택 영역과 mute/음량 조작은 별개로 둔다. 트랙을 선택하면 채팅 입력 앞에 ‘대상: 베이스’ chip이 생긴다. ‘베이스만 바꾸기’ 요청에서는 다른 트랙에 잠금 표시를 보여준다. 선택 해제도 한 번으로 가능하다.

패턴은 Strudel event를 현재 표시 구간에 투영한다. 16개 칸짜리 고정 step sequencer로 모든 곡을 바꾸지 않는다. 불규칙·연속 패턴은 비례 이벤트 띠로 표시한다. 음소거는 코드 수정이나 AI 호출 없이 즉시 동작하고 채팅에도 자동 메시지를 잔뜩 남기지 않는다.

### 플레이어

현재 곡·재생 상태·경과 시간·BPM·마스터 음량을 항상 제공한다. Strudel은 생성 패턴이라 유한한 음원 길이가 있다고 가정하지 않는다. 일반 seek bar 대신 현재 마디/반복 구간을 표시한다. 고정 길이로 내보낸 파일에만 일반 진행률·seek를 제공한다.

일시정지/재개가 같은 위치에서 가능한지는 엔진 시험으로 확인한다. 지원하지 않으면 ‘정지/처음부터 재생’으로 정확히 표시한다. 가짜 일시정지 상태를 만들지 않는다. 최초 재생은 브라우저 오디오 정책에 따라 사용자 클릭을 받는다. 이후 AI가 수정한 후보는 시작된 오디오 컨텍스트에서 자동 적용한다.

### AI 패널

사용자 문장 → 간결한 변경 요약 → 실제 적용 상태 순서로 보인다. 내부 추론이나 CLI 로그를 실시간으로 쏟아내지 않는다. 오류 세부정보는 접힌 보기로 제공한다. 요청 입력은 Enter 전송, Shift+Enter 줄바꿈을 제공하며 입력기 조합 중 Enter는 전송하지 않는다.

진행 표시에는 ‘코드 수정’, ‘실행 확인’, ‘듣는 중’, ‘분석’, ‘적용’ 중 실제 단계만 켠다. 캡처 완료 뒤 모델 응답을 기다리는 동안에는 ‘듣는 중’ 대신 ‘분석 중’이라고 쓴다. 중단 버튼은 진행 중 계속 보인다. 채팅을 접어도 상단 상태 띠에서 중단할 수 있다.

### 프로젝트와 설정

프로젝트 목록은 상단 이름 옆에서 연다. 저장·불러오기·이전 버전·코드 내보내기를 한곳에서 찾을 수 있게 한다. 설정은 UI 배율, 자동 개선 상한, AI 연결 상태, 고급 코드 보기, 맨 아래 ‘게임하기’를 포함한다. API 키·로컬 파일 경로를 매번 입력하는 제품 흐름은 만들지 않는다. 연결이 끊기면 ‘AI 연결 끊김’과 마지막 정상 시각을 보여준다.

## 6. 상태 명세

| 상태 | 보이는 내용 | 가능한 행동 |
|---|---|---|
| 첫 프로젝트 | 기본 아트, ‘어떤 음악을 만들까?’ 입력 | 자연어 요청, 기본 곡 듣기, 프로젝트 불러오기 |
| 샘플 로딩 | 필요한 소리 준비 중 | 취소. 로드 실패면 재시도 |
| 재생 중 | 실제 출력 시각화, 경과 마디·시간 | 정지/지원 시 pause, 믹서, 자연어 편집 |
| 자동 개선 | 실제 구간·단계·회수 | 언제나 중단 |
| 실행 오류 | ‘새 수정 실행 실패, 이전 버전 유지’ | 재수정, 마지막 정상 버전 |
| 오디오 모델 실패 | ‘신호 검사만 완료, 오디오 분석 실패’ | 재시도, 자동 모드 중단 |
| AI 연결 끊김 | 연결 상태와 실패한 요청 | 기존 곡 재생·수동 믹서·저장, 연결 후 다시 요청 |
| 저장 실패 | 저장되지 않음, 재시도 | 로컬 파일 내보내기, 다시 저장 |
| 작업 중 새 버전 발생 | ‘현재 곡이 바뀌어 자동 적용하지 않았어’ | 새 버전으로 요청 다시 실행 |

## 7. 접근성·움직임·인수 기준

키보드 포커스가 항상 보여야 한다. 드래그 분할선은 키보드로도 너비를 바꾸고 이름·현재 값을 읽을 수 있게 한다. 모달은 focus trap/닫기/복귀를 제공한다. 버튼·슬라이더는 기존 접근성 primitive 또는 네이티브 컨트롤을 사용한다. icon-only 버튼에는 ‘베이스 음소거’처럼 대상이 포함된 이름을 준다.

Space 재생 단축키는 입력·슬라이더 포커스에서 가로채지 않는다. Esc로 패널/모달을 닫되 AI 작업 중단과 혼동시키지 않는다. 상태 알림은 `aria-live=polite`로 의미 있는 변화만 전달하며 시간 틱마다 읽지 않는다.

전환은 120–180ms의 opacity/transform 중심으로 제한한다. `prefers-reduced-motion`에서는 장식 모션을 끄고 정적 패턴과 진행 위치로 정보를 유지한다. 오디오 엔진 시계는 애니메이션 프레임에 의존하지 않는다.

완료 판정: 세 해상도와 200% 확대에서 플레이어·입력창 겹침 없음, 긴 한국어와 오류 상태에서 잘림 없음, 키보드만으로 곡 생성·트랙 수정·저장·복구·중단·게임 왕복 가능. 시각화가 무음/정지 상태를 정확히 반영하고 코드 한 줄도 안 보고 주 흐름을 끝낼 수 있어야 한다.
