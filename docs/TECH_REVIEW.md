# olmuse 기술 검토 (VCK 기술 지침서 기준)

검토일 2026-11-09. 코드를 읽어서 찾았고, 공격이나 장애를 실제로 일으켜 보지는 않았다. AWS 계정의 실제 설정(PITR, 동시 실행 한도, 예산 알림)도 열어 보지 않았고 `deploy.ps1`에 적힌 것만 봤다.

## 결론

- 지금 가장 큰 위험은 돈이 새는 길이다. 공개 서버에서 선생님 비밀번호 하나로 운영자 키를 크레딧 없이 쓸 수 있고, 키 쪽에는 제공사 월 한도가 없으며, 장부 토큰 하나로 쿠폰(=크레딧)을 무제한 찍을 수 있다. 셋 다 돈 없이 고칠 수 있다.
- 장부 연결이 빠지면 앱이 조용히 로컬 장부로 넘어간다(fail-open). 지침서 1-5(기본은 닫혀 있다)와 정면으로 어긋난다.
- 돈 장부(DynamoDB)에 시점 복구 백업이 없고, 집 PC의 SQLite도 백업이 없다. 서버 로그도 사실상 없다. 유료 전환 전에 백업·로그·알림 세 가지는 있어야 한다.
- 구조개편 계획(FastAPI로 옮기기, 장부는 Lambda 유지, 집 PC 운영은 수익이 날 때까지)은 지침서와 맞는다. 옮길 때 지침서 6절의 쿠키·출처 확인·본문 한도·오류 응답 규칙을 처음부터 넣으면 된다.
- 커밋된 비밀값은 찾지 못했다. `.streamlit/secrets.toml`은 무시 목록에 있고 git 기록에도 없다. 문서와 시험 파일에 보이는 값은 자리표시자나 가짜다.

## 위험 순 발견 사항

### 1. [높음] 운영자 키가 크레딧 없이 쓰이고, 제공사 쪽 지출 상한이 없다

- 무엇: 공개 서버가 `STUDIO_PASSWORD`를 반드시 넣고 뜬다. 비밀번호로 들어온 세션은 크레딧 없이 운영자 키로 AI를 부른다. 비밀번호 입력에는 시도 횟수 제한이 없다. 이 풀의 상한은 앱 메모리·SQLite에 있는 하루 200회(`STRUDEL_TEACHER_DAILY_CALLS`)뿐이다. 모델 키는 이 PC의 공용 `key-pool.env`에서 읽어서, 다른 프로젝트와 같은 키를 쓴다.
- 어디:
  - `run_public.ps1:7-10` (비밀번호를 필수로 읽음)
  - `app.py:233-238` (비밀번호 로그인), `app.py:222-229` (시도 제한 없음), `app.py:297` (`teacher`면 AI 허용)
  - `app.py:44-53` (`key_pool`, `secret`이 공용 키 풀을 읽음), `app.py:86-89` (선생님 한도)
- 지침서 근거: 1-5 기본은 닫혀 있다. 비밀번호가 새면 막을 장치가 앱 안의 카운터 하나뿐이고, 그 카운터가 고장 나면(재시작, 버그) 막을 것이 없다. 1-1 추측하지 말고 잰다. `credits.py:17-18` 실측으로 한 번 호출의 최악 비용은 약 6.8센트(Gemini)다. 200회면 하루 약 13.6달러, 한 달 최악 약 400달러다. 월 예산 3만 원을 한 달이 아니라 이틀 만에 넘는다.
- 고칠 것:
  1. 사용자 결정대로 비밀번호 모드를 지우고 쿠폰으로 바꾼다. `run_public.ps1`에서 비밀번호 필수를 빼고, 공개 서버에서는 `teacher` 경로가 AI를 열지 못하게 한다. 블라인드 청취 결과(`pages/listen.py`)에 쓰는 비밀번호는 따로 이름을 붙인 값으로 분리한다.
  2. olmuse 전용 API 키를 따로 만들고 제공사 쪽에 상한을 건다. OpenRouter는 키별 크레딧 한도, Anthropic은 워크스페이스 월 지출 한도를 쓴다. Google은 예산 알림만 되고 자동 차단은 아니니, 공개 서버에서는 Gemini 키를 빼는 것도 방법이다.
  3. 비밀번호를 남기는 동안에는 세션당 시도 횟수를 제한한다.
- 비용: 0원.

### 2. [높음] 장부 설정이 빠지면 조용히 로컬 장부로 넘어간다

- 무엇: `STRUDEL_CREDITS_URL`이나 토큰 파일이 없으면 `ledger()`가 오류 없이 `.studio-data/credits.sqlite` 로컬 장부를 연다. 이때 pepper 기본값은 `"local-only"`다. 공개 서버에서 토큰 파일이 사라지거나 경로가 바뀌면 모든 계정이 새 장부에서 무료 20크레딧을 다시 받는다. 실제 구매 잔액은 보이지 않고, 운영자는 이 사실을 모른다.
- 어디: `app.py:99-107`
- 지침서 근거: 1-5. 지침서는 "환경변수 하나 빠져서 무방비 서버가 조용히 뜨는 것"을 막으려고 토큰이 없으면 서버가 아예 켜지지 않게 했다. 1-2(조용히 실패하지 않는다)에도 걸린다.
- 고칠 것: 로컬 장부는 `STRUDEL_LOCAL_AI=1`일 때만 연다. 그 밖에 원격 장부 설정이 없으면 AI를 닫고 화면에 "장부 연결 없음"을 띄운다. 시험 하나: 환경변수 없이 공개 모드로 띄우면 생성 요청이 거절되는지.
- 비용: 0원.

### 3. [높음] 장부 토큰 하나로 쿠폰을 무제한 찍을 수 있다

- 무엇: Lambda의 `/api/*`는 전부 같은 `APP_TOKEN`으로 열린다. 여기에는 쿠폰 발행(`/api/coupon_make`, 쿠폰당 최대 100만 크레딧 × 10만 회)과 보류 결제 조회(`/api/reviews`)도 들어 있다. 이 토큰은 웹 서버(집 PC)가 늘 들고 있다. 웹 서버나 이 PC의 `~/.all-tomorrow`가 털리면 크레딧을 마음대로 만들 수 있다.
- 어디: `deploy/credits/lambda_function.py:525-527` (토큰 하나로 인증), `:681-692` (쿠폰 발행), `:728-731` (경로 표), `credits.py:84-89`, `tools/coupon.py:40-43`
- 지침서 근거: 1-3 경계에서 값을 믿지 않는다. 9절의 "토큰 없는 프로세스" 원칙도 같다. 권한은 그 일을 하는 쪽에만 준다. 웹 서버는 차감·환불·조회만 하면 된다.
- 고칠 것: `OPERATOR_TOKEN`을 따로 만들어 `coupon_make`와 `reviews`는 그 토큰만 받게 한다. 이 토큰은 `tools/coupon.py`만 읽고 웹 서버 환경에는 넣지 않는다. 쿠폰 발행은 CloudWatch에 `ALERT` 한 줄을 남겨 몰래 찍히지 않게 한다.
- 비용: 0원.

### 4. [높음] 돈 장부와 집 PC 데이터에 백업이 없다

- 무엇: `deploy.ps1`은 DynamoDB 테이블을 만들지만 시점 복구(PITR)를 켜지 않는다. 잘못된 배포나 실수로 지운 항목은 되돌릴 수 없다. 집 PC의 `.studio-data/jobs.sqlite3`(진행 중 차감 기록, 작업 결과)와 `listen.sqlite`(청취 실험 결과)도 백업이 없다.
- 어디: `deploy/credits/deploy.ps1:19-23` (테이블 생성만), `studio_backend.py:1027-1033` (DB 위치가 프로젝트 폴더 안)
- 지침서 근거: 1-6 사용자 데이터는 돌아올 길이 없다. 크레딧 잔액은 돈이라 다시 만들 수 없다. 10-6에 따르면 SQLite는 `-wal`이 옆에 있으면 파일을 그냥 복사해서는 안 된다.
- 고칠 것:
  1. `deploy.ps1`에 `aws dynamodb update-continuous-backups ... PointInTimeRecoveryEnabled=true`를 넣는다.
  2. 집 PC SQLite는 작업 스케줄러로 하루 한 번 `sqlite3`의 `.backup`(백업 API)으로 다른 디스크나 OneDrive에 복사한다.
  3. 한 번은 실제로 복원해 본다.
- 비용: PITR은 테이블 크기(GB)에 비례한다. 지금 장부는 KB 단위라 월 수십 원 이하로 본다(추정, 결제 전 콘솔에서 확인). SQLite 백업은 0원.

### 5. [중간~높음] 서버 로그가 없고, 오류가 삼켜진다

- 무엇: Streamlit을 숨김 창으로 띄우고 출력을 어디에도 남기지 않는다. 작업 스레드는 예상 밖 예외를 `"internal"` 한 줄로 바꾸고 원인(traceback)을 버린다. 에셋 에이전트는 `ModelError/ValueError/LedgerError/OSError` 밖의 예외가 나면 상태가 `working`에서 멈춘다. 그러면 그 사용자는 재시작 전까지 에이전트를 다시 못 쓰고, 차감분은 재시작 때에야 환불된다.
- 어디: `run_public.ps1:27`, `run_public.ps1:36` (출력 버림), `studio_backend.py:1297-1299` (예외 삼킴), `asset_agent.py:167` (잡는 예외가 좁음)
- 지침서 근거: 1-2 조용히 실패하지 않는다. 10-7 로그 규칙(본문 금지, 이름+값 기준 가림, 보관 기한).
- 고칠 것:
  1. `logging`으로 날짜별 파일에 남긴다(`.studio-data` 밖, 7일 보관).
  2. 이메일·키·쿠폰 코드는 값 기준으로 가린다. `redact()`(`studio_backend.py:382`)를 넓혀서 쓴다.
  3. 요청 본문(곡·대화)은 남기지 않는다.
  4. `_run`의 `except Exception`에서 traceback을 로그로 보낸다. `asset_agent._run`은 `except Exception`으로 넓혀 환불하고 `failed`로 닫는다.
- 비용: 0원.

### 6. [중간] 서버에 이메일 평문과 작업 내용이 남고, 처리방침이 실제와 다르다

- 무엇:
  - 장부는 이메일을 HMAC으로만 두는데, 집 PC의 `jobs.sqlite3`는 `owner = "acct:" + email`과 `charges.email`을 평문으로 저장한다. 작업 결과(곡 코드, 대화)도 보관 기한 없이 쌓인다.
  - 개인정보처리방침에는 기본 모델 경로인 OpenRouter(DeepSeek)가 빠져 있다. "작업물은 브라우저에 저장"이라고 적혀 있지만 진행 중·끝난 작업 결과는 서버에도 남는다.
  - 국외 이전에 필요한 항목(이전받는 자, 국가, 일시·방법, 보유 기간, 거부 방법)과 보호책임자·연락처 형식도 없다.
- 어디: `app.py:295`, `studio_backend.py:975-976`, `studio_backend.py:985`, `pages/privacy.py:14`, `pages/privacy.py:18`, `pages/privacy.py:21-26`, `pages/privacy.py:32`
- 지침서 근거: 10-7(민감정보를 로그·저장소에 남기지 않는다), 1-7(확인하지 않은 것은 적는다). 처리방침은 지침서 범위 밖이지만, `SERVER_PLAN_RESEARCH.md` 5절의 결론과 같다.
- 고칠 것:
  1. 서버 저장 키를 `"acct:" + HMAC(email)`로 바꾼다. 장부와 같은 pepper를 쓰거나 별도 pepper를 쓴다.
  2. 끝난 작업 결과는 30일 뒤 지운다.
  3. 처리방침에 OpenRouter와 서버 보관 항목을 넣고, 국외 이전 표를 법정 항목대로 채운다. 사업자등록 뒤에는 사업자 정보와 보호책임자를 넣는다.
- 비용: 0원(법률 검토를 맡기면 별도).

### 7. [중간] 장부 Lambda에 호출량·비용 방어선이 없다

- 무엇: Function URL이 인증 없이(`auth-type NONE`) 열려 있다. 토큰 검사는 함수 안에서 하므로 토큰 없는 요청도 Lambda 호출로 과금된다. 동시 실행 한도(reserved concurrency)와 AWS 예산 알림이 없다. `ALERT` 로그에 걸린 경보도 연결돼 있지 않다(EDGE_CASES 5절).
- 어디: `deploy/credits/deploy.ps1:42` (함수 생성, 동시 실행 한도 없음), `deploy/credits/deploy.ps1:55-57` (공개 URL), `deploy/credits/lambda_function.py:289-290` (ALERT 로그만)
- 지침서 근거: 7-5 시간·크기 상한의 정신을 비용에 옮기면, 상한 없는 것은 장기 실행에서 사고가 된다(5-3 "모든 장수명 Map에 상한"과 같은 원리).
- 고칠 것:
  1. `put-function-concurrency --reserved-concurrent-executions 10`을 건다.
  2. AWS Budgets에 월 5달러 알림을 둔다.
  3. CloudWatch 메트릭 필터 `ALERT`에 경보를 걸고 이메일로 받는다.
- 비용: Budgets 알림 2개까지 무료, CloudWatch 경보 10개까지 무료다. 동시 실행 한도는 0원이다.

### 8. [중간] 의존성 버전이 고정되지 않았고, Streamlit 한계가 남아 있다

- 어디: `requirements.txt:1-4`, `app.py:379`
- 지침서 근거: 13-7 의존성 관리. 2-2 "안 쓰는 것·죽은 것은 뺀다"(Streamlit을 떠나는 계획과 같은 방향).
- 고칠 것: `pip freeze`로 잠금 파일(`requirements.lock`)을 만들고 서버는 그것으로 설치한다. FastAPI로 옮기면 Streamlit 고정 문제는 사라진다.

- 고칠 것: 표와 1단계를 "완료, 남은 것: 강제 종료 후 환불 실측"으로 고친다.
- 비용: 0원.

## 구조개편 계획에 대한 판단

| 계획 항목 | 지침서와 맞나 | 덧붙일 것 |
|---|---|---|
| FastAPI 한 프로세스 + 기존 화면 | 맞다. 화면은 이미 독립돼 있고, 필요 없는 다리(Streamlit)를 걷어내는 것은 2-2와 같다 | 지침서 6-1 ②~④와 6-2를 처음부터 넣는다. 세션 쿠키는 `HttpOnly; Secure; SameSite=Lax`(구글 로그인에서 돌아올 때 Strict면 쿠키가 안 붙는다). 상태를 바꾸는 POST는 `Sec-Fetch-Site`/`Origin` 확인, `Host`는 `olmuse.app`만. 본문 한도는 인증 뒤·파싱 앞에 두고 500은 `{"error":"internal"}`만 보낸다. 세션 비밀키가 없으면 서버가 뜨지 않게 한다(1-5). `127.0.0.1` 바인드는 지금처럼 둔다 |
| 장부는 Lambda+DynamoDB 유지 | 맞다. 멱등 ref, 조건부 트랜잭션, 이메일 HMAC이 이미 있다 | 위 3번(토큰 분리), 4번(PITR), 7번(동시 실행 한도) |
| 서버 돈은 수익 뒤, 그때까지 집 PC + 터널 | 지침서는 호스팅 위치를 정하지 않는다. 차감이 호출 시점이라 서버가 꺼져 있어도 사용자 돈이 사라지지 않는다. 그래서 이 결정은 감당할 만하다 | 다만 1-6에 따라, 집 PC에서 운영하는 동안 곡을 서버에 저장(이전 순서 7단계)하는 것은 미루기를 권한다. 다른 디스크로 가는 백업이 없으면 돌아올 길이 없는 데이터가 된다. 재부팅 후 자동 시작(작업 스케줄러)과 Windows 업데이트 사용 시간 설정은 0원으로 할 수 있다 |
| 쿠폰으로 선생님 모드 대체 | 맞다. 1-5 쪽으로 가는 변화다 | 쿠폰 발행 권한을 웹 서버에서 떼는 것(3번)이 함께 가야 한다 |
| 나중에 데스크톱 프로그램, 영업비밀은 서버에 | 1-3·9절과 같은 생각이다. 클라이언트는 믿지 않는다 | 프로그램에는 어떤 API 키도 넣지 않고, 서버 API를 사용자 로그인 토큰으로만 부른다. Electron이면 8절 표 전부가 첫 커밋부터 필요하다. 14-4는 "넓게 배포하면 코드 서명"이라고 한다. Windows 코드 서명 인증서는 연 수십만 원 단위라 월 3만 원 예산과 맞지 않는다(가격은 확인하지 않음). 수익 전에는 웹앱(설치형 PWA 포함)만 두고, 프로그램은 인맥 대상 서명 없는 배포로 한정하는 편이 맞다 |
| 월 예산 3만 원 이하 | 고정비는 지금 거의 0이다(Lambda·DynamoDB 사용량 과금) | 가장 큰 변동비는 모델 API다. 크레딧으로 받지 않는 지출(비밀번호 모드, 가입당 무료 20크레딧 ≈ 최악 0.85달러)만 예산에서 나간다. 1번을 고치면 무료 크레딧만 남는다. 토스페이먼츠 가입비 22만 원과 연 11만 원은 결제를 열 때 예산과 따로 본다 |

## 고칠 순서

1. **비밀번호 모드 끄기와 전용 키 상한**: 공개 서버에서 크레딧 없이 AI를 부를 길이 없다. olmuse 전용 키에 제공사 월 한도가 걸려 있다. (1번)
2. **장부 fail-closed**: 원격 장부 설정 없이 공개 모드로 띄우면 AI가 닫히고 화면에 이유가 보인다. 시험이 이를 고정한다. (2번)
3. **운영자 토큰 분리**: 웹 서버의 토큰으로 `coupon_make`를 부르면 401이 나고, `tools/coupon.py`는 운영자 토큰으로만 발행된다. (3번)
4. **백업**: PITR이 켜져 있고(`describe-continuous-backups`로 확인), 집 PC SQLite가 매일 다른 곳으로 복사되며, 각각 한 번 복원해 본 기록이 있다. (4번)
5. **로그와 알림**: 날짜별 로그 파일에 traceback이 남고 이메일·키가 가려지며 7일 뒤 지워진다. Lambda `ALERT`와 AWS 예산 알림이 메일로 온다. 동시 실행 한도가 걸려 있다. (5·7번)
6. **환불 누락과 오류 문구**: 엔진이 예상 밖 예외를 던져도 잔액이 그대로이고, 화면에는 내부 문구가 나가지 않는다. 에셋 에이전트가 `working`에 멈추지 않는다. (9·10번, 5번의 에이전트 부분)
7. **서버 저장 이메일 해시화와 처리방침 갱신**: `jobs.sqlite3`에 이메일 평문이 없고, 끝난 작업은 30일 뒤 지워진다. 처리방침의 외부 전송 목록이 코드의 공급자 목록(OpenRouter 포함)과 같다. (6번)
8. **의존성 잠금, 조사 문서 갱신**: 잠금 파일로 같은 버전이 설치되고, 조사 문서의 현재 구조와 1단계 상태가 코드와 같다. (8·11번)
9. **FastAPI 이전**: 조사 문서의 이전 순서 2~5단계를 위 표의 지침서 6절 항목과 함께 진행한다. 끝난 기준은 조사 문서의 기준에 더해, 토큰·쿠키 없이 403, 다른 출처 POST 403, 틀린 Host 403을 시험이 매번 확인하는 것이다.
