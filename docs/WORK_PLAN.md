# 남은 작업 계획

사용자 요청을 빠짐없이 적은 목록이다. 위에서부터 하나씩 끝내고, 끝나면 `[x]`로 바꾼 뒤 커밋한다. 일정은 적지 않는다.

## 1. 음악 화면 묶음 (olmuse, 예전 이름 strudel 딸깍이)

- [x] 1-1 둥근 모서리를 아이폰식 연속 곡선으로. 끝난 기준: 두 화면 모두 `corner-shape: squircle` 적용, 원형 요소는 그대로 원.
- [x] 1-2 지난 그림을 팝업 대신 책장으로. 앨범을 하나씩 꺼내 보는 애니메이션. 끝난 기준: 길게 누르면 책장이 열리고, 방향키·휠·클릭으로 꺼내고, 고르면 커버가 바뀐다.
- [x] 1-3 단순한 앨범커버 제거. 끝난 기준: 32개 견본 시트에서 단순한 그림이 없다.
- [x] 1-4 저장·내보내기 위치 통일. 끝난 기준: 모든 도구줄에서 저장·내보내기가 오른쪽 끝, 대화상자 주 버튼이 오른쪽 끝.
- [x] 1-5 의미 없는 저장 버튼 삭제. 저장은 자동. 끝난 기준: 상단에 저장 버튼이 없고 새로고침해도 곡이 남는다.
- [x] 1-6 저장됨 표시 축소, 시간 삭제.
- [x] 1-7 자동 개선을 AI 입력창 옆으로 이동. 끝난 기준: 이름과 설명이 보이고 켜고 끌 수 있다.
- [x] 1-8 자동 개선 절차 보강. 끝난 기준: 회차마다 원래 목표와 이전 시도를 AI가 받고, 끝날 때 가장 점수가 높은 버전이 남는다. 단위 시험 통과.
- [x] 1-9 처음 열었을 때 생기는 미세한 스크롤 제거. 끝난 기준: 900, 800px 높이에서 페이지와 중간층 모두 스크롤이 없다.
- [x] 1-10 앨범커버처럼 숨은 기능을 설정 설명에 적기.

## 4. 게임 소리: 튜토리얼

- [x] 4-1 게임 소리 화면이 무엇이고 어떤 순서로 쓰는지 간단히 알려 주는 튜토리얼. 끝난 기준: 처음 열면 보이고 닫을 수 있으며 다시 열 수 있다.

## 5. 게임 소리: 린트를 AI 쪽으로 옮기기

린트는 사용자가 다루는 도구가 아니다. AI가 결과물을 사용자에게 내놓기 전에 강제로 검토하고 고치게 만드는 장치다.

- [x] 5-1 사용자에게 보이는 린트를 없앤다: 린트 전용 화면, 상단 버튼과 숫자, 타일 표시, 상세 탭, 규칙 편집.
- [x] 5-2 AI가 에셋을 만들거나 고치면 사용자에게 보이기 전에 린트를 돌리고, 걸리면 AI가 스스로 고친다. 횟수 한도를 둔다.
- [x] 5-3 사용자에게 고치라고 시키지 않는다. 남은 문제는 AI가 바로 고친다. 7-3에서 바꿨다.
- [x] 5-4 내보내기는 막지 않고, 남은 문제는 경고로 알린다.
- [x] 5-5 `docs/GAME_ASSET_PLAN.md`의 린트 절을 이 구조로 고친다.

## 7. 자동 개선과 게임 소리 사용성

- [x] 7-1 자동 개선 횟수를 막대로 정한다. 0은 꺼짐, 최대 5번. 끝난 기준: 고칠 게 없거나 3점 미만으로 오르면 한도 전에 멈춘다. 단위 시험 통과.
- [x] 7-2 타일을 누르면 선택, 길게 누르면 큰 창. 타일 위 버튼과 자세히 버튼을 없앤다.
- [x] 7-3 "AI가 고치지 못한 문제" 안내와 고쳐 줘 버튼을 없앤다. 자체 검사가 이름과 저작권까지 고친다.
- [x] 7-4 한 에셋에 시안 여러 개 요청. 개수 선택이나 "시안 3개"라는 말로 1~4개. 듣고 하나를 채택하면 나머지는 버전 기록에 남는다.
- [x] 7-5 환경음은 끊기지 않게 만들고 계속 재생한다. 끝난 기준: 환경음 4종이 이음매, 음량 차, 끊김 규칙을 통과하고 끝까지 재생돼도 멈추지 않는다.

## 8. 공개와 로그인

- [x] 8-1 이름을 olmuse로 바꾼다. 내부 환경 변수 `STRUDEL_*`와 Lambda `strudel-credits`는 그대로 둔다.
- [x] 8-2 공개 주소 https://olmuse.app. `run_public.ps1`이 이름 있는 터널 `olmuse`를 띄우고, 터널이 죽으면 5초 뒤 다시 띄우며 앱이 죽었으면 앱도 다시 띄운다.
- [x] 8-3 크레딧, 모델·추론 수준 선택, 코드 탭(트랙·악보 옆).

## 9. 할일 (지금은 안 함)

여기 적은 것은 나중에 할 일이다. 사용자가 시작하라고 할 때 한다.

- [ ] 9-1 가격 정하기. 사용자가 블라인드 청취를 충분히 한 뒤 결과를 알려 주면 쓸 모델을 정하고, 그 모델의 호출 원가로 크레딧 가격을 계산한다.
- [ ] 9-2 구독제 설계. 크레딧 충전과 함께 둔다.
- [ ] 9-3 용량 팔기 검토. 크레딧이 일정 이상이면 그 크레딧으로 만들 수 있는 음원의 용량을 계산해 저장 용량으로 준다. 계산값을 그대로 주지 않고 사업적으로 다듬어 정한다.
  - 참고 어림값(조사 전): 효과음 하나 20~200KB, 배경음 3분 OGG 160kbps 약 3.6MB, 모바일 게임 소리 전체 10~50MB, 인디 PC 게임 50~300MB. 실제 값은 이 일을 할 때 다시 잰다.
- [ ] 9-4 하루 AI 호출 총량 `STRUDEL_DAILY_CALLS=200`(모든 계정 합계)을 손님이 늘었을 때 올린다. 친구들에게 돌리면 금방 찬다.
- [ ] 9-5 계정당 동시 생성 1개 제한을 돈 버는 요소로 쓰기. 예: 구독이나 상위 요금에서 동시 생성 수를 늘린다. 9-2와 함께 정한다.

공용 컴퓨터는 따로 배려하지 않는다. 공용 컴퓨터를 쓰는 사람들은 그곳의 규칙이 이미 있다.
