# 게임 소리 에셋 작업실 계획

순서와 끝난 기준만 적는다. 첫 구현은 데이터가 가짜인 프론트엔드 껍데기이고, 사람이 화면을 확인한 뒤 백엔드를 붙인다.

현재 상태: 껍데기(`studio_frontend/asset_studio/`, 가짜 데이터 `data.js`)에 보드, 선택과 동시 수정, 확대, 명세, 튜토리얼, 시안 여러 개, 환경음 루프, 게임 폴더 연결이 들어 있다. 8절 순서 3(nkido 어댑터 시험)은 통과했다. 순서 4~6의 계약은 [ASSET_BACKEND_SPEC](ASSET_BACKEND_SPEC.md)에 있다.

## 1. 무엇을 만드나

olmuse 음악 화면이 곡 하나를 깊게 만드는 화면이라면, 이 화면은 게임 하나에 들어가는 소리 수십 개를 한꺼번에 다룬다. 첫 시선은 에셋 전체이고, 첫 행동은 하나씩 들어보기다. 결과물은 실제 게임에 넣는 파일이므로 듣는 소리, 검사하는 소리, 내보내는 소리가 같은 파일이어야 한다.

## 2. 엔진 판단

| 도구 | 라이선스 | 판단 |
|---|---|---|
| nkido (Akkado + Cedar) | MIT | 기본 엔진. 효과음과 음악, stem이 모두 되고 TINProject에서 쓰고 있다. 저장소 규모가 작고(별 8개, 저작권자 1인) 웹에서 WAV를 내는 경로는 찾지 못했다. |
| jsfxr | Unlicense | 효과음 보조 엔진. Node에서 WAV 출력이 확인됐고 레트로 효과음이 빠르다. |
| Tone.js | MIT | nkido가 막힐 때의 음악 대안. 서버 WAV 렌더는 아직 검증 전이다. 막히면 Elementary. |
| Strudel | AGPL-3.0 | 이 화면에서 쓰지 않는다. 음악 화면에만 남긴다. |

Strudel 공식 FAQ는 만든 음악은 사용자 것이라고 적지만 상업 사용 조항은 없다. 앱 코드에는 AGPL 의무가 있고, 게임 런타임에 넣으면 게임도 자유 라이선스여야 한다. 예제와 트랙은 AI 학습 금지라 프롬프트 자료로 쓰지 않는다. 기본 샘플도 뱅크마다 라이선스가 달라 쓰지 않는다. 법률 판단이 아니라 원문을 읽은 사실이다.

렌더는 서버에서 한다. nkido 파이프라인이 Windows CLI이고 린터가 실제 파일을 재야 하기 때문이다. 엔진은 어댑터 하나로 감싸 `render(source) → WAV + stems`만 약속한다. 서버 원본은 48 kHz WAV이고 채널 수를 함께 적는다. 화면은 그 파일을 디코드해 쓴다. 음원은 CC0(VCSL, Kenney 등)로 시작한다.

nkido 어댑터 시험(8절 순서 3)에서 떨어지면 효과음만 jsfxr 값 방식으로 먼저 붙인다. AI가 jsfxr 값(JSON)을 내고 브라우저가 렌더한다.

## 3. 화면

### 전환

우상단에 `게임 소리` 버튼을 둔다. 누르면 재생 중인 곡이 멈추고, 트랙의 색 막대들이 조각으로 흩어져 에셋 타일 격자로 다시 모인다. 돌아갈 때는 반대로 재생한다. 동작 줄이기 설정에서는 페이드만 쓴다.

상단바는 두 화면이 같다. 높이, 여백, 버튼 크기, 아이콘을 맞추고 맨 오른쪽 전환 버튼은 같은 자리에 둔다. 같은 뜻의 버튼은 두 화면에서 같은 아이콘을 쓴다.

### 에셋 보드 (전체 조망)

```text
┌──────────────────────────────────────────────────────────────┐
│ [폴더] 게임 이름   샘플 12 · 승인 30      [명세][내보내기][음악] │
├──────────┬───────────────────────────────────────────────────┤
│ 분류     │  UI                                               │
│ UI    14 │  ┌────┐ ┌────┐ ┌────┐ ┌────┐ ┌────┐               │
│ 전투  22 │  │파형│ │파형│ │파형│ │파형│ │파형│               │
│ 환경   8 │  │클릭│ │확인│ │취소│ │코인│ │실패│               │
│ 음악   6 │  │0.2s│ │0.4s│ │0.3s│ │0.8s│ │1.1s│               │
│          │  └────┘ └────┘ └────┘ └────┘ └────┘               │
│ 상태     │  전투                                             │
│ 필터     │  ...                                              │
├──────────┴───────────────────────────────────────────────────┤
│ ▶ 전체 듣기   선택 3개 ×   [ 더 가볍고 짧게 바꿔줘         ] ↑   │
└──────────────────────────────────────────────────────────────┘
```

- 타일은 파형, 이름, 길이, 상태 색을 보여 준다. 음악은 타일이 더 넓다.
- 타일에 올리면 바로 들린다. 방향키로 옮기면 그 소리가 자동 재생된다. `전체 듣기`는 분류 순서대로 이어서 재생하고 지금 나오는 타일을 표시한다.
- 들으면서 키 하나로 승인하거나 수정 표시를 한다.

### 여러 개 수정

- Ctrl 클릭, Shift 범위, 끌어서 선택. 아래 입력창 하나로 동시에 보낸다.
- 타일마다 진행 상태가 따로 보이고, 끝난 타일에 새 버전 표시가 붙는다.
- 이전과 새 버전을 번갈아 들으며 타일별로 채택하거나 버린다. 선택 전체를 일괄 채택할 수도 있다.

### 에셋 확대

타일이 커지면서 화면을 채운다(공유 요소 전환). 음악 화면의 트랙 화면을 그대로 옮겨 온다. 타일은 누르면 선택, 길게 누르면 이 큰 창이다.

- 큰 파형, 스펙트럼, 재생선
- stem 트랙 행: 켜기/끄기, 혼자 듣기, 음량, 활동 시각화
- 이 에셋에 대한 AI 대화, 소스 코드, 버전 기록
- 라이선스 카드. 린트 결과는 보이지 않는다(아래 내보내기 절)

### 샘플 후 확장

1. 게임 설명과 에셋 목록을 받는다.
2. 대표 샘플 몇 개만 만든다. 분류마다 1~2개.
3. 사람이 듣고 승인, 수정, 다시 뽑기를 한다.
4. 승인한 샘플에서 스타일 기준을 뽑아 고정한다.
5. 나머지를 그 기준으로 확장한다. 보드에는 대기 타일이 먼저 깔리고 채워진다.

### 명세 주고받기

- `프롬프트 복사`: 음악 작업 에이전트에게 붙여 넣을 프롬프트와 명세 양식을 복사한다.
- 명세를 붙여 넣거나 파일로 올리면 형식을 검사하고, 추가/변경/삭제될 에셋을 보여 준 뒤 실행한다.
- 상주 에이전트는 아래 바의 입력창이다. 따로 떠 있는 대화창·패널을 만들지 않고, 답은 알림(토스트)과 되돌리기로만 보인다.
- 인수인계 질문은 명세를 쓰는 외부 에이전트가 한다. `프롬프트 복사`의 프롬프트가 기획서, 코드, 사용자와 이미 나눈 대화로 먼저 채우고 그래도 정해지지 않은 것만 한 번에 하나씩 묻게 하고, 답은 명세의 `style`과 `references`에 담긴다. olmuse는 받은 `references`를 프로젝트 레퍼런스로 넣을 뿐 질문 화면을 두지 않는다. 화면에 새 요소를 넣는 결정은 만들기 전에 사용자에게 묻는다.

### 내보내기와 저작권

- 린트는 사용자에게 보이지 않는다. AI가 결과를 내놓기 전에 스스로 돌리고 이름과 저작권까지 고치는 장치다. 사용자에게 고치라고 하거나 "고쳐 줘" 버튼을 내밀지 않는다.
- 내보내기는 막지 않는다. 못 고친 문제가 있으면 경고한다.
- 묶음에는 파일, 명세, 린트 보고서, `CREDITS.md`, 사용 도구와 음원의 라이선스 원문이 들어간다.
- `저작권 전체 복사`는 이 게임에 쓰인 모든 고지를 한 번에 복사한다.
- 묶음은 zip이다: `game-audio.spec.json`, `audio/<id>.wav`(승인한 것), `CREDITS.md`, `lint-report.json`. 명세의 각 에셋에는 `status`, `origin`(`made`|`imported`), 가져온 것은 `source_file`·`license`·`holder`, 만든 것은 `prompt`가 붙는다. 승인 안 된 에셋은 파일 없이 명세에만 남아 다시 열면 빈 칸이 된다.

### 게임 폴더에 바로 반영 (웹)

실제 개발 중에는 소리를 고칠 때마다 내보내기, 압축 풀기, 게임 폴더에 복사하기를 되풀이하게 된다. 설치 프로그램 없이 웹에서 게임 폴더에 바로 쓰게 한다.

- 방법: Chrome·Edge의 File System Access API로 게임의 소리 폴더를 한 번 연결한다. 연결 정보는 브라우저 저장소(IndexedDB)에 두고 다음 방문에도 쓴다. 브라우저가 권한을 풀었으면 처음 쓸 때 한 번 다시 허락받는다.
- 쓰기: 승인하는 순간 그 소리 파일을 내보내기와 같은 경로·형식(형식, 샘플레이트, 폴더 규칙, 루트 폴더, 엔진)으로 바로 쓴다. 승인한 소리를 고쳐 다시 승인하면 덮어쓴다. `game-audio.spec.json`과 `CREDITS.md`도 함께 고친다. 승인 취소나 삭제는 파일을 지우지 않는다(게임이 그 파일을 쓰고 있을 수 있다).
- 읽기: 보드가 아직 견본 소리일 때만, 연결하면서 폴더 맨 위의 `game-audio.spec.json`과 소리 파일을 가져오기와 같은 규칙으로 올린다(숨김 폴더·node_modules 제외). 작업이 있는 보드는 폴더 내용으로 덮지 않고, 연결하는 순간 승인한 소리를 모두 폴더에 쓴다.
- 저장·동기화 단추를 두지 않는다. 쓰기에 실패했을 때만 알린다.
- Godot은 에디터로 돌아오면 바뀐 파일을 다시 불러온다. 그래서 "고치기 → 승인 → 게임에서 바로 듣기"가 된다.
- 연결과 연결 끊기는 내보내기 창의 "게임 폴더" 칸에 있다(사용자 결정, UI_LESSONS 규칙 2).
- 한계: Firefox·Safari에서는 연결 항목을 숨기고 지금의 zip 내보내기를 쓴다. 브라우저를 닫은 동안에는 반영되지 않는다.
- 이것으로 모자랄 때의 다른 길: 게임 쪽 AI 에이전트가 MCP로 받아 가기(6절), Godot 에디터 플러그인, 설치형 프로그램. 설치형은 서명 없이 배포할 수 있고, Microsoft Store에 MSIX로 올리면 서명이 무료다(TECH_REVIEW 133행).

### 이미 작업한 게 있는 사람 (가져오기)

처음 화면 머리줄의 `가져오기` 단추, 보드 맨 위 안내, 첫 방문 사용법 창 세 곳에서 들어간다. 화면 아무 데나 끌어다 놓아도 된다. 무엇을 넣었는지는 화면이 알아본다.

- 소리 파일(wav/mp3/ogg 여러 개, 폴더째): 파일·폴더 이름으로 분류와 이름을 짐작해 바로 보드에 올린다. 폴더 이름은 게임 이름이 된다. 가져온 직후 창에 이름·분류·라이선스 칸이 줄마다 나오고 고치는 즉시 반영된다. 짐작이 약한 분류는 노란 테두리. "직접 가져옴" 표시, 라이선스는 비워 두고 묻지 않는다(내보내기 창 저작권 칸에서 나중에 적음, 비어 있으면 내보낼 때 경고).
- 내보낸 묶음(zip 또는 푼 폴더): 명세대로 보드를 다시 세우고 하던 데서 잇는다.
- 소리 목록(한 줄에 하나, 또는 머리줄 있는 CSV): 빈 칸으로 올라가고 `AI로 채우기`가 채운다.
- 가져온 소리의 확대 화면 `이 느낌으로 시안`: 같은 분류의 빈 칸(없으면 새 칸)을 그 소리를 기준으로 채운다. AI 프롬프트에 기준 소리의 길이·최대·음량·저/중/고역 비율·밝기·앞뒤 무음을 넣는다. 빈 칸을 채울 때도 같은 분류의 가져온 소리가 있으면 기준으로 쓴다. 프롬프트는 확대 화면 코드 탭에 보이고 호스트에 `asset:prompt`로 보낸다.
- 사용자 작업이 처음 들어오면 견본 보드(별빛 정원)는 치운다.

## 4. 데이터

보드의 주인은 브라우저다. 보드, 버전, 소리는 브라우저 IndexedDB에 있고 서버는 보드를 갖지 않는다. 기기 사이에 이어 하기는 하지 않는다. 설계 검토 근거는 `BACKEND_DESIGN_REVIEW.md`에 있다.

- `game-audio.spec.json`은 교환용이다. 지금 화면이 내보내는 형식 그대로 고정하고, 가져오기·내보내기·Godot·게임 폴더가 이 형식을 쓴다.
- 버전 레코드는 spec과 따로 둔다: 작업 id, 엔진, 소스, 측정값, 출처 목록, 프롬프트, 모델, 소리 키. 소리는 버전마다 따로 저장한다.
- 서버는 생성 결과를 기한을 두고 임시 보관만 한다. 기한이 지나면 다시 받을 수 없다.
- CREDITS는 승인된 버전의 출처 목록을 합쳐 만든다. 출처 기록이 없는 에셋은 린트 오류다.

### 생성 작업과 전송

- 생성과 소리 전송은 FastAPI의 HTTP로 한다: 작업 id 발급, 상태 확인, 소리 받기. Streamlit은 서명 토큰만 iframe에 넘긴다. Streamlit 위에 임시 경로를 만들지 않는다.
- 에이전트 호출(지금 구조)과 생성 작업은 따로다. 생성 작업은 에셋·시안 단위의 작업 id를 보드에 저장하고, 새로고침하면 다시 붙는다.
- 서버 전체의 동시 작업 수를 제한한다. 취소할 수 있고, 일부만 실패하면 실패한 만큼 돌려준다.

### 요금과 키

- 과금 단위는 소리 1개의 시안 1개다. AI 자체 수정은 그 안에 포함한다. 여러 개를 한꺼번에 만들기 전에 예상 크레딧을 보여 준다.
- 수수료는 비슷한 서비스의 수수료와 엇비슷하게 둔다. 값은 API 원가가 정해진 뒤 조사해서 정한다.
- 모델 호출은 프록시 하나를 거친다. 키 여러 개를 넣고 싼 것부터 쓴다. all-tomorrow의 LiteLLM을 쓰는 안을 먼저 본다.
- 비밀번호 세션에서도 생성을 쓸 수 있다.

| 음악 음량 | -20 LUFS 근처, 믹스 -26~-14 | TIN 파이프라인 |
| 모바일 / 콘솔 프로필 | -18 ±2 / -24 ±2 LUFS | ASWG-R001 2차 출처. 원문 미확인 |
| 형식 | 48 kHz, 지정 비트와 형식 | TIN 파이프라인 |
| 이름 | 분류 접두어 규칙 | 프로젝트 설정 |

추가 검사: 클리핑, 길이 범위, 앞뒤 무음, DC 오프셋, 루프 이음새 튐, 라이선스 기록.

## 6. MCP

미룬다. 게임 폴더 연결이 spec과 파일을 폴더에 쓰므로 외부 에이전트는 폴더를 읽으면 된다. 서버가 보드를 갖지 않아 아래 도구는 지금 구조에서 성립하지 않는다.

도구: `list_assets`, `get_asset`, `get_spec`, `put_spec`, `request_edits`(여러 개 동시), `render`, `lint`, `export`, `get_license`.

- 모든 응답에 `license` 항목을 넣는다.
- 서버 지시문에 라이선스 고지 의무를 적고, 내보내기 결과에 고지 파일 경로를 돌려준다.
- 호출 한도는 서버가 강제한다.

## 7. 공개

- 화면은 `studio_frontend/asset_studio/`에 두고 음악 화면을 iframe으로만 연결한다. Strudel과 게임 파일을 import하지 않으므로 나중에 그대로 별도 저장소로 뺄 수 있다.
- 공개 라이선스는 MIT로 정했다. 이 폴더만 별도 저장소로 떼어 공개한다. Strudel을 포함한 현재 저장소에 넣은 채 공개하면 AGPL-3.0-or-later가 되므로 그렇게 하지 않는다.
- TINProject는 라이선스가 없고 패치와 곡 데이터는 게임 고유물이다. 코드도 데이터도 옮기지 않고, 상류 nkido에 직접 어댑터를 새로 쓴다.
- 이 저장소의 `analyze_audio.py`는 TINProject에서 복사한 파일이다. 공개 전에 새로 쓰거나 허락을 받는다.

## 9. 위험

- nkido의 Windows 빌드가 공개 저장소 사용자에게 장벽이다. 이 PC는 상류 저장소를 clang으로 직접 빌드한 실행 파일을 쓰고, 경로는 환경 변수 `OLMUSE_NKIDO`로 바꾼다. 실행 파일이 없으면 생성만 꺼지고 나머지 화면은 돈다.
- 자연어로 Akkado를 쓰는 AI 정확도: `tools/akkado_trial.py`로 쟀다. 공개 사이트 기본 모델, 추론 강도 low, 안내서 `asset_engine/akkado_guide.md`를 시스템 프롬프트로 준 조건에서 요청 72개(효과음 36, 환경음 18, 음악 18) 중 첫 시도 통과 67개, 오류를 돌려줘 고친 뒤 통과 72개다. 요청당 평균 약 20초, 0.002달러다. 기본 추론 강도에서는 답이 잘려 고친 뒤 통과가 48개 중 43개였다. 통과는 오류 없이 렌더되고 무음과 클리핑이 아니며 효과음이 끝나고 음악에 stem이 있다는 뜻이고, 요청한 소리처럼 들리는지는 사람이 듣는다.
- 실행 격리: `asset_engine/nkido.py`가 파일·주소·장치에 닿는 구문을 실행 전에 거부하고, 빈 임시 폴더에서 30초, 메모리 1 GB, 자식 프로세스 금지로 돌린다. 세 제한은 `tests/test_asset_engine.py`가 확인한다. 네트워크는 운영체제 수준에서 막지 않고 구문 거부에 기댄다.
- 재미와 모션 판단은 시험으로 끝나지 않으므로 사람 확인을 끝난 기준으로 둔다.

## 환경음 제작 규칙

환경음은 한 번 재생되는 소리가 아니라 끝없이 이어지는 바닥이다. 백엔드도 이 방식으로 만든다.

- 페이드 인과 페이드 아웃을 넣지 않는다. 바닥 소리는 처음부터 끝까지 이어진다.
- `루프 길이 + 0.5초`를 렌더하고 초과분을 머리에 동일 전력으로 접는다. 완성 파일을 뒤에서 자르지 않는다.
- 길이는 8초나 16초. 음량 변화는 루프 길이의 정수 배 주기로만 넣는다.
- 타닥거림이나 빗방울 같은 사건은 불규칙한 간격으로 넣어 반복이 들리지 않게 한다.
- AI 자체 검사: 이음매 도약, 끝과 처음의 음량 차 3 dB 이하, 가장 조용한 0.25초가 평균보다 12 dB 이상 낮지 않을 것.
- 환경음 재생은 항상 반복이다. 올려서 듣기로 시작했으면 포인터가 떠날 때 멈춘다.

## 시안

한 요청으로 시안을 1~4개 받을 수 있다. 시안은 한 소리의 변주가 아니라 같은 설명을 각자 다르게 읽은 별개의 곡이다. 시안마다 다른 생각을 미리 정해 주고, 다 만든 뒤에도 사실상 같은 곡으로 들리는 시안은 한 번 다시 만든다(추가 크레딧 없음, 자세한 것은 [ASSET_BACKEND_SPEC](ASSET_BACKEND_SPEC.md)의 "시안 겹침"). 사용자는 이전 버전과 시안을 번갈아 듣고 하나를 채택한다. 채택되지 않은 시안은 버리지 않고 버전 기록에 둔다. 모두 버리면 이전 버전이 유지된다.
