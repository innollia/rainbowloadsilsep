# olmuse UI 시행착오

음악 작업실(`studio_frontend/`)과 에셋 작업실(`studio_frontend/asset_studio/`)에서 사용자가 되돌리거나 다시 시킨 UI를 모았다. 따옴표 안은 사용자 원문이다. 화면 명세는 [STRUDEL_UI](STRUDEL_UI.md), 에셋 작업실의 상주 에이전트·인수인계 결정은 [GAME_ASSET_PLAN](GAME_ASSET_PLAN.md) 82~83행에 있다.

## 규칙

1. **새 UI가 가장 적게 생기는 해석을 고른다.** 요청이 기존 요소로 풀리면 그걸로 푼다. (사례 17, 18)
2. **새 창·패널·줄·대화상자는 구조 결정이다.** 만들기 전에 대화로 묻는다. (사례 17, 18)
3. **그 단계의 주인을 먼저 정한다.** 다른 에이전트가 할 일을 우리 화면에 만들지 않는다. (사례 18)
4. **이미 정해진 것은 다시 묻지 않는다.** 기획서·코드·지난 대화로 채우고 남은 것만 묻는다. (사례 18)
5. **빼라면 빼기만 한다.** 그 자리를 다른 문구나 요소로 채우지 않는다. (사례 15)
6. **질문에는 답만 한다.** 물음을 수정 지시로 읽고 고치지 않는다. (사례 14)
7. **껍데기 화면 먼저, 백엔드는 나중.** 화면을 다듬고 나서 붙인다. (사례 1, 16)
8. **단추보다 직접 조작.** 누르기·길게 누르기·우클릭·F2·아이콘으로 풀고 글자 단추와 상단 단추를 줄인다. 자주 안 쓰는 것은 설정·메뉴 안에 숨긴다. (사례 5, 6, 7, 10, 11, 12)
9. **사용자가 몰라도 되는 것은 화면에 두지 않는다.** AI가 고칠 수 있는 문제 알림, 뜻 모를 단계 이름, 쓸모없는 개수 표시는 뺀다. (사례 5, 11, 13)
10. **실제로 보이는지 확인한다.** 글자 대비, 캐시로 빈 화면, 여백 비대칭은 사용자가 먼저 찾았다. (사례 3, 9, 12)
11. **UI 문구는 흔히 쓰는 말로 쓴다.** 지어낸 우리말(올리면 듣기, 모양, 구분자, 앞말, 층, 되살리기) 대신 다른 프로그램에서 보던 말(마우스 오버 시 재생, 형식, 구분 기호, 접두사, 레이어, 복원)을 쓴다. `091f146`
12. **정보는 사용자가 쓰는 단위로 둔다.** 결국 통째로 쓰는 것(저작권 목록)은 항목마다 나눠 두지 않고 한곳에서 한 번에 복사하게 한다. 같은 앱의 두 화면은 크기·배치 값을 맞춘다. (사례 19)
13. **비전문가가 쓰는 도구다.** 전문 용어(파라미터, 스템, 페이드 인 구간), 사용자가 직접 적는 id, 사용자를 재촉하는 말을 화면에 두지 않는다. 미리 듣기 소리는 화면을 떠나거나 빈 곳을 누르면 멈춘다. (사례 20)

### 20. 11-10 에셋 작업실 조작과 동적 소리
- 반응: 마우스 오버 재생이 다른 화면에 가도 안 멈춤, 분류 안에서 새 소리를 만들면 전체 분류로 감, 새 소리는 우클릭으로만 다룰 수 있음, 동적 소리 창이 "전문가스러운 말"이고 id를 직접 적게 하고 레이어 관리가 모자람, "완료 버튼이 없음. 누른 다음에 설정을 하나라도 바꾸면 그제서야 실제 음원목록에 나오게", 가져오기·내보내기 아이콘이 뒤바뀜, 내보내기에 필요 없는 것, 시안 개수 선택이 불편함, 고른 소리가 계속 울리고 빈 곳을 눌러도 선택이 안 풀림, 분류 레퍼런스 안내 문장, "AI로 채우기", "확인할 에셋이 아직 1개나 남았잖아, 빨리 해~"는 재촉.
- 결과: 미리 듣기는 손을 떼거나 창·화면을 옮기면 멈추고 보드에서는 한 번만 재생, 빈 곳을 누르면 선택과 소리를 해제. 빈 소리도 누르면 선택, 꾹 누르면 "만들기"가 있는 상세 화면. 동적 소리는 id 칸을 없애고 쉬운 말로, 레이어마다 음량·레벨 막대·이것만 듣기·끄기, 첫 변경 때 목록에 들어감. 시안 개수는 보드에서도 1~4 단추이고 고른 값이 남음. 내보내기에서 샘플레이트·비트·품질·묶음 목록을 뺌.
