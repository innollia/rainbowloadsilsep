# olmuse 기상천외한 상황 목록

사람이 실제로 저지를 법한 엉뚱한 행동과 환경을 모으고, 지금 코드가 어떻게 하는지 읽어서 확인했다.
상태: **없음** (대비 없음) / **부분** (일부만) / **대비됨**. 영향: 사용자가 잃는 것의 크기(큼/중간/작음). 난이도: S/M/L.
같은 표 안에서는 영향 큰 순서다. 일정은 적지 않는다.

## 7. 센스 있게 알아서 처리할 것 (외부 자료·유명 서비스 사례)

웹의 UX 원칙 글과 유명 서비스의 업데이트·도움말에서 "사용자가 말하지 않아도 알아서 해 주는" 처리를 골라 olmuse에 맞췄다. 출처 번호는 문서 끝 링크 목록.

### 7-1. 출처별 핵심 (요약)

| 출처 | 핵심 |
|---|---|
| [1] Raskin, *Never Use a Warning When You Mean Undo* | 사람은 경고창을 습관적으로 넘긴다. 지울 수 있는 곳에는 확인창 대신 되돌리기를 둔다. Gmail은 묻지 않고 지우고 되돌리기를 준다 |
| [2] Nielsen 10 휴리스틱 | 5번 오류 예방(실수를 못 하게 만드는 게 오류 메시지보다 낫다), 9번 오류에서 회복(무슨 일인지, 어떻게 하면 되는지) |
| [3] Laws of UX: Doherty threshold, Postel's law | 400ms 넘게 걸리면 반응했다는 표시를 바로 준다. 입력은 너그럽게 받고 출력은 일정하게 |
| [4] Falsehoods programmers believe (이름·시간 등 모음) | 이름은 겹치고 바뀐다. 시계와 시간대는 틀린다. 가정하지 말 것 |
| [5] Ink & Switch, Local-first software | 기다림 없는 반응, 여러 기기에서 같은 작업, 오프라인 작업, 오래 남는 데이터, 사용자 소유 |
| [6] web.dev, Persistent storage / Storage for the web | `navigator.storage.persist()`가 허락되면 브라우저가 localStorage·IndexedDB를 지우지 않는다. Safari는 스크립트 저장소를 7일 미사용 시 지울 수 있다 |
| [7] Figma, *Behind the feature: autosave* + 오프라인 도움말 | 연결이 끊기면 변경을 디스크에 써 두고 다시 연결되면 올린다. 탭을 닫아도 남는다 |
| [8] VS Code hot exit | 저장 안 한 파일도 닫을 때 백업하고 다시 열면 그대로 돌려준다(묻지 않음) |
| [9] Notion 휴지통 | 지운 페이지는 30일 동안 휴지통에서 되살릴 수 있다 |
| [10] Gmail Undo Send | 보내기를 몇 초 늦춰 그 사이 취소할 수 있게 한다(기본 5초, 최대 30초) |
| [11] Linear changelog, Fixes & improvements | 매 릴리스 끝의 작은 개선 목록을 "Quality of Life"라 부르며 중요하게 여긴다. 예: 접은 사이드바 구역 기억, 복사한 링크에 적용 중인 필터 포함, 바깥에서 이미지 끌어다 놓기 |
| [12] Google Chat persistent drafts | 보내지 않은 메시지를 자동 저장하고 기기 사이에 동기화(30일 보관) |
