### TINProject 재사용

확인한 구현: `C:/projects/TINProject/tools/nkido_pipeline/tool/analyze_audio.py` 및 같은 폴더의 README §9.

- WAV에서 LUFS, true peak, 클리핑, DC, 주파수 대역, 채널 상관도, 루프 연결을 측정하는 기존 분석기다. `--selftest`도 있다.
- 16-bit PCM WAV 입력이며 K-weighting 계수는 48 kHz 기준이다. 브라우저의 실제 sample rate를 기록하고 분석 입력을 48 kHz로 정규화하거나 계수를 보정해야 한다.
- 이 코드는 **신호 분석기**다. 장르·악기·분위기를 이해하는 오디오 모델 호출이라고 간주하지 않는다.
- `tools/`, `docs/`, `.claude/`의 이번 조사에서는 사용자가 말한 별도 오디오 이해 모델 커넥터의 진입점을 확인하지 못했다. 없다고 단정하지 않는다. 0단계에서 해당 경로·입출력·모델을 확정한 뒤 재사용한다. 그 전에는 음성 이해 완료로 보고하지 않는다.
- TINProject의 옛 `docs/STRUDEL_AUDIO.md`는 이후 nkido로 전환된 조사 기록이다. 현재 Strudel API의 근거로 그대로 복사하지 않는다.
- TINProject의 게임용 Strudel 제외 결정은 이 제품의 명시적 Strudel 사용 요청에 확대 적용하지 않는다. 실제 옮길 코드·샘플의 이용 조건은 별도로 확인한다.

## 3. 실행 구조

```text
브라우저: 작업실 UI + 숨긴 Strudel REPL + Web Audio + 패턴/스펙트럼 표시
   │ 명령·프로젝트 변경·캡처 전달 / 작업 진행·후보 버전 수신
Streamlit: 소유자 인증·입력 검증·저장·작업 등록·결과 전달
   │
관리형 Postgres: 프로젝트·버전·채팅·작업·진행 이벤트
   ↑ PC 작업기가 인증 후 바깥으로 요청하여 작업 수령
내 PC: 제한된 작업 폴더 + Antigravity CLI + 기존 오디오 분석 도구
```

음악 엔진과 시각화는 브라우저, 저장과 작업 관리는 Python, CLI는 PC에 둔다. Community Cloud에서 사용자 PC의 `localhost`나 이 채팅의 MCP를 호출할 수 있다고 가정하지 않는다. 이 세션에 연결된 Antigravity 도구는 제품의 런타임 API가 아니다.

초기에는 로컬 Streamlit과 같은 PC 작업기로 종단 흐름을 검증한 뒤 Cloud에 화면을 올린다. PC 작업기가 꺼져 있어도 저장된 곡의 재생·수동 믹서·프로젝트 읽기는 가능해야 한다. AI 요청은 연결 끊김으로 표시하고 무기한 대기시키지 않는다. PC 없이 항상 AI를 쓰려면 나중에 CLI 실행기를 별도 서버로 옮기며 인증·실행 환경을 다시 검증한다.

### Streamlit와 재생 수명

작업실을 하나의 지속되는 custom component로 묶는다. Components v2를 먼저 검증하고, 고정 `key`로 기존 인스턴스를 갱신한다. REPL·AudioContext·플레이어는 Python rerun마다 재생성하지 않는다. 안정적인 키만으로 무중단이 보장된다고 보지는 않으며 채팅·저장·상태 갱신 중 연속 재생을 실측한다.

Strudel은 `@strudel/repl`, `@strudel/core`, `@strudel/webaudio` 등 실제 공개 export를 확인해 재사용한다. 편집기는 고급 보기로 숨기고 엔진·샘플 로더·패턴 시각화는 유지한다. 공식 웹사이트를 단순 cross-origin iframe으로 넣는 방식은 코드 편집·출력 캡처 제어가 제한되므로 제품 본체의 방식으로 선택하지 않는다. 유지보수 중단으로 표시된 `@strudel/react`에 새로 의존하지 않는다.

재생 시계·볼륨·시각화는 JS 안에서 동작한다. Python에는 사용자 명령, 저장, 확정된 믹서 변경, 코드 적용 결과만 전달한다. PCM 배열을 Streamlit의 위젯 상태로 매 프레임 왕복시키지 않는다. 캡처 바이너리의 전달 방식은 0단계에서 검증하고, 직접 전송이 안 맞으면 인증된 제한 업로드 경로를 사용한다.

### 생성 코드 격리

생성 Strudel 코드는 JavaScript이므로 신뢰하지 않는다. 외부 사이트 iframe 대신 **패키지를 직접 구성하되 생성 코드를 실행하는 sandbox iframe**을 둔다. `allow-scripts`만 우선 허용하고 부모 DOM·스토리지·인증 토큰에 접근시키지 않는다. Components v2의 Shadow DOM은 보안 격리가 아니다.

허용된 샘플 출처만 네트워크로 접근하도록 CSP를 제한하고, 출처·CORS·AudioWorklet 동작을 함께 검증한다. 부모와는 정해진 메시지만 주고받고 `source`·요청 nonce·schema·크기를 확인한다. 전역 `eval`로 부모 화면에서 코드를 실행하지 않는다. 무한 연산으로 UI를 멈추는 후보의 중단·iframe 재생성 경로도 검증한다. 격리와 Strudel 실행이 양립하는지가 초기 출시 게이트다.

## 4. Antigravity CLI 연결

공식 headless 문서에서 `agy -p`, JSON 출력, `stream-json`, conversation ID, JSON schema 옵션을 확인했다. 실제 설치된 CLI의 출력 계약과 종료 동작은 구현 시 검증한다. 현재 문서의 streaming 입력은 text block만 지원하므로 WAV를 해당 입력에 넣으면 모델이 듣는다고 가정하지 않는다.

초기에는 작업마다 한 번 실행하고 해당 프로젝트의 conversation ID를 명시적으로 저장한다. 전체 PC의 ‘최근 대화’를 쓰는 `--continue`는 프로젝트 혼선을 만들 수 있어 사용하지 않는다. 프로세스 재사용은 시작 지연이 문제일 때 도입한다.

1. 작업기가 DB의 `queued` 작업을 원자적으로 점유한다. 단일 작업만 실행한다.
2. 작업 ID별 임시 폴더에 현재 코드·변경 범위·목표·에러·분석 결과만 제공한다.
3. CLI는 고정 실행 인자와 stdin으로 호출한다. 사용자 문장을 셸 명령 문자열에 이어 붙이지 않는다.
4. 출력은 구조화된 후보로 받는다. stdout 이벤트, stderr 진단, 최종 상태, 실제 산출물 모두 확인한다. 종료 코드 0만으로 성공 처리하지 않는다. headless 권한 거절이 soft-deny로 끝날 수 있다.
5. schema 검증과 변경 범위 검증을 통과한 후보만 브라우저에 전달한다.
6. 브라우저가 실제 실행하고 반환한 오류·캡처를 다음 수정 입력으로 쓴다. CLI 프로세스 자체가 브라우저 오디오 엔진은 아니다.

커넥터 기능은 `read_project`, `propose_patch`, `get_runtime_error`, `request_capture`, `get_analysis` 정도로 한정한다. 초기에는 전용 파일/작업 이벤트 계약으로 연결하며 MCP 서버는 CLI의 도구 호출이 필요해진 경우에만 추가한다. 모델이 명령 실행·전체 파일 탐색을 할 필요가 없는 경로를 우선한다.

작업 폴더만 지정하는 것은 접근 제한이 아니다. 실행기 전용 OS 계정 또는 실효성이 검증된 sandbox와 ACL로 다른 프로젝트·홈·브라우저 프로필 접근을 막는다. CLI 인증은 OS 인증 저장소의 기존 로그인 경로로 제공하고 복사·출력하지 않는다. DB 비밀값과 전체 저장소는 에이전트 환경에 넘기지 않는다. 무조건 권한 승인 옵션을 제품 기본값으로 쓰지 않는다.

## 5. 코드·트랙·수정 범위

임의 Strudel 프로그램을 매번 정규식으로 뜯어 드럼과 베이스로 분리하지 않는다. 앱이 생성하는 곡은 전역 설정과 트랙별 코드 블록으로 관리하고 Strudel 프로그램으로 합성한다.

| 데이터 | 최소 내용 |
|---|---|
| 프로젝트 | ID, 이름, 소유자, BPM, 박자/사이클 기준, 현재 버전, 생성·수정 시각 |
| 트랙 | 안정된 ID, 역할, 이름, 코드 블록, mute, gain, 색상 |
| 버전 | 부모 ID, 전체 코드/트랙 snapshot, 변경 요약, 생성 주체, 실행 결과 |
| 채팅 | 프로젝트 ID, role, 내용, 관련 작업·버전 ID |
| AI 작업 | 요청 ID, 기준 버전, 대상 트랙, 목표, 반복·시간·호출 한도, 상태 |
| 분석 | 버전·캡처 hash, 실제 구간, sample rate, 수치, 모델·판정, 실패 사유 |

“베이스만 바꿔줘”이면 해당 track ID만 교체할 수 있다. 잠긴 드럼과 전역 설정의 hash가 달라지면 후보를 거절한다. BPM 등 전역 변경이 필요한 경우 범위 확대를 표시하고 묻는다. 사용자가 전역 변경을 요청한 경우에는 그대로 수행한다.

채팅 작성 중 사용자가 믹서를 바꾸거나 버전을 되돌렸으면 `base_revision` 불일치 결과를 자동 적용하지 않는다. 변경 범위를 다시 맞춘다. 최초에는 마지막 정상 버전을 재생하면서 후보를 검증하고, 성공한 후보를 다음 cycle 경계에 적용하는 경로를 검증한다. 불가능한 경우 짧은 정지 후 적용 사실을 표시한다.

외부 코드를 불러왔는데 트랙 분리가 불가능하면 ‘전체 곡’ 한 트랙으로 재생한다. 분리 가능하다고 가장하지 않는다. 고급 편집과 내보내기에서는 원본 Strudel 텍스트를 제공한다.

Strudel의 cycle과 BPM을 혼동하지 않는다. `BPM = cps × 60 × beats_per_cycle`로 표시하며 4 beats/cycle에서 240 BPM이면 1 cps다. 트랙별 fast/slow는 해당 패턴 속도이고 전역 BPM과 구분한다.

## 6. 귀와 자동 피드백

### 실제 출력 캡처

마스터 출력 그래프를 확인해 monitor branch로 분기하고, 실제 재생된 오디오를 캡처한다. 마이크나 시스템 전체 녹음을 기본으로 쓰지 않는다. 녹음 분기를 스피커에 한 번 더 연결해 음량을 중복시키지 않는다. 수집은 AudioWorklet/지원되는 기존 캡처 구현 중 가장 작은 경로를 택한다.

시각화도 실제 FFT와 pattern event를 사용한다. 무음인데 움직이는 가짜 파형은 만들지 않는다. 음성 분석용 파일에는 믹서 mute·gain, BPM, 버전, 시작·종료 cycle, 실제 sample rate를 붙인다. 사용자 마스터 볼륨과 분석 지점의 관계도 기록해 서로 다른 믹스를 비교하지 않는다.

기본 캡처는 8초, 목표 패턴이 더 길면 최대 16초 안에서 조정한다. 저속·긴 패턴은 일부 구간 평가임을 표시한다. WAV를 신호 분석기에 전달하고 동일한 캡처를 기존 오디오 이해 도구에 전달한다. 신호 분석은 숫자로 판단 가능한 결함, 음성 모델은 악기·밀도·분위기 등 요청과의 부합도를 담당한다. 신호 수치로 음악적 완성도를 대신 판정하지 않는다.

### 상태와 정지 규칙

`대기 → 코드 수정 → 실행 확인 → 캡처 → 신호 검사/오디오 분석 → 목표 비교 → 적용 또는 다음 수정 → 완료`

- 자동 모드는 기본 OFF. ON이면 ‘최대 3회, 회당 최대 16초 청취’를 표시한다.
- 한 번의 사용자 요청에 개선 최대 3회, 실행 오류 재수정 최대 2회, 전체 벽시계 5분을 초기 상한으로 둔다. 어느 한도든 먼저 도달하면 멈춘다.
- 코드 수정 호출 최대 5회, 오디오 이해 호출 최대 3회. 자동 후속 호출·숨은 재시도를 허용하지 않는다. 정확한 비용을 알 수 없는 구독 CLI에는 확정 금액 대신 호출·토큰/사용량·남은 회수를 표시한다.
- 별도 과금 오디오 모델은 사전 설정된 예산과 보수적 요청당 상한을 확인한 뒤 호출한다. 가격/사용량을 알 수 없어 예산을 보장하지 못하면 비용 한도를 보장한다고 표시하지 않는다.
- 목표 충족, 두 번 연속 개선 없음, 실행 실패 한도, 시간·예산 한도, 사용자 중단, 탭 이탈/캡처 timeout, 작업기 연결 끊김 중 하나면 종료한다.
- ‘중단’은 예약된 다음 호출을 즉시 취소하고 CLI 프로세스 트리·캡처를 중지한다. 이미 전송한 외부 요청 비용을 되돌릴 수 있다고 약속하지 않는다. 사용자가 직접 정지하지 않았다면 마지막 정상 음악 재생은 유지한다.
- 늦게 도착한 결과는 cancelled 작업에 적용하지 않는다. 모든 이벤트에 작업·버전 ID를 붙인다.

표시 예: ‘00:08–00:16 듣는 중’, ‘신호 검사: 클리핑 발견’, ‘오디오 분석: 베이스가 드럼을 가린다는 추정’, ‘베이스 수정 중 · 2/3’.

모델이 WAV를 실제로 처리한 응답과 캡처 ID가 있어야 ‘오디오 분석 완료’라고 쓴다. 코드만 읽은 평가는 ‘코드 검토’, 수치만 측정한 것은 ‘신호 검사’다. 모델 연결이 실패하면 해당 단계를 실패로 남기고 ‘들었다’고 쓰지 않는다. 자동 루프는 완전한 청취 기능 없이 출시하지 않는다.

## 7. 저장·복구·보안

프로젝트 snapshot과 변경 채팅을 한 트랜잭션으로 저장한다. 복구는 과거 기록을 삭제하지 않고 새 버전을 만든다. 저장 UI는 ‘변경 있음 → 저장 중 → 저장됨 / 실패’를 구분하고 서버 확정 전 성공이라고 표시하지 않는다. Cloud 로컬 디스크와 `st.session_state`는 영구 저장소로 쓰지 않는다.

초기 저장은 Postgres JSONB snapshot으로 충분하다. 음성 캡처는 같은 공급자의 private object storage에 일시 보관하고, 처리 후 삭제한다. 초기 TTL은 24시간이며 분석 수치·구간·hash만 남긴다. 전체 오디오를 버전마다 영구 복제하지 않는다. DB 복구와 파일 내보내기를 둘 다 확인한다.

소유자 1명만 AI 실행 가능하도록 서버 인증과 소유자 허용 검사를 둔다. 공개 URL을 아는 것만으로 PC에 작업을 넣을 수 없어야 한다. CLI·DB·음성 모델 인증정보는 브라우저·Git·채팅·로그에 넣지 않는다. 작업기에는 전용 최소 권한 credential을 주고 프로젝트 소유권·파일 크기·mime·시간 제한을 검증한다. 사용자 업로드를 `static/`에 저장하지 않는다.

작업은 lease/heartbeat로 관리하고 중복 요청 ID는 재실행하지 않는다. 작업기가 죽으면 lease 만료 후 실패로 돌리고 유료 모델 호출을 자동 재시도하지 않는다. 음악 재생을 위해 페이지가 살아 있어야 하는 단계에는 짧은 응답 제한을 둔다.

## 8. 기존 웹을 이스터에그로 남기기

설정 안에 ‘게임하기’를 두고 누르면 기존 아케이드로 진입한다. 그 안에서 BLACK BOX 09에도 접근한다. 음악 작업실에서 게임은 기본 메뉴나 첫 화면 카드로 노출하지 않는다. `st.navigation`의 표시를 숨기더라도 게임 페이지 등록과 직접 진입 동작은 유지한다.

게임 진입 전 프로젝트·현재 믹서 상태를 저장하고 음악과 자동 개선을 중단한다. 게임에서 ‘음악 작업실로 돌아가기’를 제공하며 프로젝트 상태는 복구하되 재생은 사용자 클릭으로 시작한다. 게임의 사운드와 음악이 겹치지 않게 한다. 기존 게임 CSS가 음악 UI에 남지 않도록 페이지 전환을 검증한다.

## 9. 최적화 기준

아래 수치는 보장된 성능이 아니라 초기 측정·수정 기준이다.

| 영역 | 설계 | 검증 기준 |
|---|---|---|
| 오디오 | 브라우저 로컬 scheduling, 렌더 루프와 분리 | 채팅·저장 중 엔진 재초기화 0회, 청취상 끊김 없음 |
| 믹서 | 드래그는 로컬 즉시 반영, 끝에서 저장 | 음소거/볼륨 반응 목표 50ms 이내 |
| 시각화 | 기본 30fps, 숨긴 탭/정지 상태에서는 중지 | 일반 작업 중 긴 main-thread 작업과 audio underrun 기록 |
| 왕복 | 재생 시간과 FFT는 서버 전송 금지 | 상태 폴링 기본 2초, 유휴 시 중지/간격 확대 |
| 샘플 | 필요한 악기만 로드·캐시, URL·버전 고정 | 콜드/웜 구분, 로드 완료 전 무음 성공 처리 금지 |
| 최초 화면 | 게임·고급 편집기·오디오 분석 의존성 지연 로드 | 일반 회선에서 조작 가능 3초 목표, Cloud cold start 별도 기록 |
| 캡처 | 한 번에 하나, 기본 8초/최대 16초 | 48kHz stereo PCM16 16초는 약 3.1MB, 변환 메모리 별도 제한 |
| 분석 | 기존 numpy 분석기 재사용 | 캡처·모델 요청 한 번씩, 동일 hash·모델·목표 결과 재사용 |
| 저장 | snapshot은 변경 때만, 채팅 50개 단위 조회 | 실패한 저장을 재생 경로에서 기다리지 않음 |
| CLI | 동시 실행 1개, 요청 컨텍스트는 현재 곡 중심 | 시작 지연/수정/캡처/분석 시간을 분리 측정 |
| 게임 | 들어갈 때만 로드 | 음악 초기 화면에서 게임 WASM/PCK 다운로드 0 |

`st.cache_resource`에는 공유해도 되는 DB 연결 등만 둔다. 프로젝트·대화·인증 상태를 전역 cache에 섞지 않는다. 백그라운드 작업 중 UI가 중단 버튼을 처리할 수 있어야 하므로 긴 CLI 실행을 Streamlit 요청 안에서 동기 대기하지 않는다.

## 10. 구현 순서와 완료 조건

| 단계 | 결과물 | 통과 조건 |
|---|---|---|
| 0. 기술 검증 | 최소 Strudel component, agy 어댑터 시험, 귀 경로 확인 | rerun 중 연속 재생·코드 적용·오류 반환·실제 WAV 캡처·sandbox 동작·CLI schema/중단 확인. 기존 음성 모델 커넥터 경로 확정 |
| 1. 음악 작업실 | UI 명세대로 화면, 기본 곡·트랙·플레이어 | 코드 없이 재생·선택·mute·gain·BPM 조정. 큰 글씨와 키보드 사용 가능 |
| 2. 자연어 편집 | agy 작업기, 대상 트랙 수정·실행 오류 재수정 | ‘베이스만’ 요청에서 드럼 hash 유지, 실패 후보 미적용, 중단 가능 |
| 3. 저장 | 프로젝트 목록·채팅·버전·복구·내보내기 | 새로고침/재배포 후 복구, 동시 수정 감지, 저장 실패 표시 |
| 4. 귀·자동 개선 | 신호+모델 분석·실시간 진행·상한 | 실제 캡처 근거 표시, 모든 종료 조건과 늦은 결과 무시 검증 |
| 5. 이스터에그·Cloud | 설정 게임 진입, Streamlit 배포 설정·운영 안내 | 기존 게임 회귀 검사, 배포 후 소유자 인증·PC 연결·저장·음악 재생 확인 |

단계마다 실제 사용할 수 있는 상태를 남긴다. 0단계가 막히면 보이는 껍데기를 먼저 완성해 연결 가능하다고 보고하지 않는다. 공개 공유 기능·앨범 이미지 생성·전체 DAW 타임라인·상시 서버 CLI는 뒤로 미룬다.

### 필요한 검증 묶음

- 기존 `tests/test_engine.py`, `tests/test_catalog.py` 회귀 검사.
- 불변 트랙, 잘못된 schema, 오래된 기준 버전, 중복 작업, cancel 뒤 도착한 결과, 복구 snapshot 검사.
- 무음·클리핑 fixture로 캡처와 신호 분석 연결 확인. TINProject 분석기 자체 `--selftest` 재사용.
- 실제 브라우저에서 재생 중 채팅/저장/rerun, 샘플 실패, 자동재생 제한, AudioContext resume, PC 종료·탭 닫기 확인.
- 1280×720 / 1920×1080 / 2560×1440, 200% 확대, 채팅 접힘/펼침, 긴 프로젝트명·오류 상태 확인.
